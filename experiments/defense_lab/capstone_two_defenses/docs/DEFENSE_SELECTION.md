# 방어 기법 선정 근거

## 과제와 현재 구현의 연결

과제는 직접·간접 인젝션 20종 이상, 두 가지 이상 방어 구현, 공격 성공률 감소와 정상 기능 저하를 함께 보고하도록 요구한다. 원본 main bdc899d6900f17cf4418fd2375074c50b69d4a0a의 이메일 요약기 호출과 시스템 프롬프트를 복사해 두 기법을 연결했다. 원본 서비스에는 적용하지 않았다.

| 기법 | 선정 이유 | 구현 |
|---|---|---|
| 입력 필터링 | 추가 모델·학습 데이터 없이 판정 근거를 재현할 수 있다. 지시 덮어쓰기, 역할 사칭, 특수 토큰과 인코딩 우회를 사전 검사한다. | YAML 규칙, 한·영 구문, NFKC·제로폭·HTML·base64·hex·URL 인코딩 검사. 검사용 사본만 정규화하고 허용 원문은 보존한다. |
| 명령·데이터 분리 프롬프트 | 이메일과 첨부 추출문을 같은 비신뢰 데이터 경로로 처리하며, 원문에 있는 명령을 상위 지침과 구분한다. 필터에 없는 표현에도 적용되는 보완층이다. | 원본 시스템 지침에 데이터 취급 정책을 추가하고 XML 이스케이프와 요청별 무작위 경계를 적용한다. |

두 기법은 기존 UI의 off/filter/separate/both와 일치한다. 기본 OFF를 유지해 기준선과 단독·결합 비교가 가능하다. 필터는 모델 호출 전 차단하고 분리 프롬프트는 허용 입력의 구성만 바꾸므로 책임도 분명하다. 별도 판정 LLM 호출은 없으며 분리 정책만 입력 토큰을 추가한다.

출력 검증은 없는 URL·전화번호·행동 지시를 판정할 때 정상 업무 요청과 날짜 등을 오탐할 수 있어 별도 보정이 필요하다. 분류기는 대표성 있는 학습·검증 데이터 또는 추가 판정 모델 비용이 필요하다. 이번 두 기법은 현재 데이터와 평가 구조에서 원인을 설명하기 쉽다는 이유로 우선 선정했다. 나머지 기법이 무효라는 뜻은 아니다.

## 근거와 한계

OWASP LLM01:2025는 외부 콘텐츠 분리, 행동 제한, 입력·출력 검사와 적대적 시험을 권고한다. OWASP Prevention Cheat Sheet는 정규화·인코딩 우회와 구조화 프롬프트를 다루면서 필터 우회와 오탐도 경고한다. 따라서 단어 하나가 아니라 지시 구문을 검사하고 원문을 보존했다. XML과 랜덤 경계는 모델이 강제하는 보안 경계가 아니며, 규칙 탐지만으로 인젝션을 완전히 막을 수 없다.

## 검증 결과와 적용 판단

현재 서비스의 읽기 전용 데이터 API로 공격 69건, 검토 완료 정상 이메일·기준 요약 100건, 기존 첨부 추출문 19건을 스냅샷으로 가져왔다. 예제 정상 데이터 5건은 평가에서 제외했다. 공격은 직접 50건·간접 19건이며, 활성 카테고리는 시스템 프롬프트 유출 29건, 지시 덮어쓰기 30건, 비가시 문자 10건이다. 역할 사칭·특수 토큰은 단위 테스트로 확인했지만 실제 등록 시나리오가 없어 실데이터 성능을 주장하지 않는다.

자동 테스트 36개 통과. 169건 × 4설정 × 3회 = 2,028건 Mock 경로 검증에서 오류 0건이다. 고유 공격 입력 69건 중 필터 탐지 9건(13.04%), 정상 100건 중 입력 필터 차단 0건이다. 나머지 공격 60건은 모델로 전달 가능하므로 탐지율만으로 충분한 방어라고 판단할 수 없다. 분리 프롬프트는 입력을 차단하지 않는 변환 기법이다.

**실제 모델 호출은 0회다. ASR·최종 FPR·ROUGE-L·실제 토큰·서비스 지연 효과는 미측정이며 적용 판단은 보류다.** Mock 응답은 기준 요약을 복제하지 않는다. 결과의 해당 지표를 null로 기록해 가짜 개선을 만들지 않는다.

실제 비교 시 같은 고정 스냅샷·모델·temperature로 설정별 3회 실행하고 직접/간접·카테고리별 ASR, 정상 차단 또는 거부 FPR, ROUGE-L, 입력/출력 usage, 평균/p95 지연을 비교해야 한다. 기존 공격 판정과 ROUGE 계산을 복사본에서 재사용한다. API 오류와 레이트 리밋을 실패 공격으로 섞지 않는다. 기준 요약은 평가에만 쓰고 모델에 보내지 않는다. 기존 네 방어 실험의 수치를 이번 두 방어의 효과로 전용하지 않는다.
