# 실험 결과 조회와 모델별 지표

현재 소스의 조회 기능과 집계 기준을 설명한다. 이메일 요약기는 결과를 현재 화면에만 반환하고, 실험 결과에는 공격 실험·정상 응답 확인·성능 평가만 포함한다. 아래의 최초 구현·운영 검증 절은 이 변경 전의 과거 기록이다. 기능 커밋 `7bba550`의 Railway/Sites 버전 22 배포 증거는 [당시 운영 검증 기록](verification/2026-11-11-results-release.json)을 참고하며, 현재 소스의 배포 완료를 뜻하지 않는다.

## 화면과 조회 범위

- 실험 결과 탭 상단의 **웹에서 진행한 실험**은 공격 실험·정상 응답 확인·성능 평가 기록을 최신 등록 순서로 보여준다. 한 페이지에 최대 5개를 표시하며 이전/다음 페이지로 해당 세 종류의 전체 이력을 조회한다. 기존 이메일 요약 기록은 목록·건수·페이지 수에서 제외한다.
- 하단의 **모델 별 실험 기록**과 비교 그래프는 DB의 실제 실행을 집계한다. 과거 9월 30일 발표자료 수치를 이 화면의 집계나 오류 시 대체값으로 사용하지 않는다. 대시보드의 별도 과거 실험 소개는 이번 변경 범위 밖이다.
- 공격 실험, 정상 응답 확인, 성능 평가의 세 탭을 구분해 선택한다. 공격 실험에는 전체/직접/간접 경로 필터가 있고, 모델 선택은 조회된 모델별 지표를 화면에서 걸러 보여준다.
- 모델 행의 **실험 기록 보기**는 해당 모델·제공자·실험 종류·공격 경로로 상단 목록을 필터링한다. **전체 실험 보기**로 해제한다. 목록의 처리 수는 해당 실험 전체 실행 기준이다.
- 공격 기록의 결과 보기는 기존 공격 결과 상세를 연다. 성능 평가 기록은 모델 수에 따라 기존 단일 모델 평가 또는 모델 별 비교 결과 화면으로 연결한다.
- CSV는 현재 표시한 실제 모델 지표를 내보낸다. 누락값은 빈 필드로 유지하고, 수식으로 해석될 수 있는 문자열을 이스케이프한다.
- 방어 전후 비교는 구현 예정 안내만 표시한다. 이번 모델별 집계는 방어 OFF 실행만 포함하며 방어 ON, FPR 또는 방어 적용에 따른 변화량을 계산하지 않는다.

조회 API는 읽기 전용 트랜잭션을 사용한다. 시나리오·입력·응답·판정·실행 기록을 수정하거나 다시 채점하지 않으며 모델을 호출하지 않는다. 집계 범위는 DB에 저장된 해당 조건의 전체 실행으로, 상단에서 보고 있는 5개나 기존 목록 API의 최근 100개로 제한되지 않는다.

## 이메일 요약기의 저장 정책

`POST /api/summarize`는 본문 및 첨부파일 요약 결과·사용량·응답시간을 즉시 반환한다. DB 설정 유무와 관계없이 새 실험·케이스·실행·모델 호출·판정 기록을 만들지 않고, 입력 메시지와 요약 출력도 DB에 저장하지 않는다. 성공 응답의 `database`는 `{saved: false, mode: "transient"}`이며 `experimentId`와 `runId`를 발급하지 않는다. 요약 결과는 현재 브라우저 화면에서 확인하며 새로고침 후 DB에서 복원하지 않는다.

파일 업로드는 별도 흐름이다. 업로드한 원본과 추출 텍스트·메타데이터는 기존 첨부 저장소/DB에 보관한다. 첨부 요약은 서버가 저장된 추출 결과를 읽어 요청 메시지를 구성할 뿐, 새 요약 실행 기록을 추가하지 않는다. 공격 실험·정상 응답 확인·성능 평가의 입력 스냅샷과 실행 결과 저장은 유지한다.

기존 `purpose=summary` 실험 및 연결된 입력·응답·호출 기록은 삭제하지 않는다. 결과 목록·집계에서는 제외하지만 ID를 알고 있으면 기존 상세 API로 조회할 수 있다. 이번 변경에는 DB 마이그레이션이나 데이터 삭제가 없으며, 연결 풀·캐시·집계/렌더링 최적화도 포함하지 않는다.

## API

### 실험 목록

`GET /api/experiments?page=1&pageSize=5`

| 매개변수 | 동작 |
| --- | --- |
| `page` | 1 이상 정수. 마지막 페이지보다 크면 마지막 페이지로 조정한다. |
| `pageSize` | 1~100 정수, 페이지 조회 기본값 5. 웹 화면에서는 5로 고정한다. |
| `purpose` | `attack`, `normal`, `performance`. 생략 또는 `all`은 이 세 종류의 전체다. `summary`는 HTTP 400으로 거절한다. |
| `vector` | `all`, `direct`, `indirect`. 직접/간접은 공격 종류 또는 전체 종류 조회에서만 허용한다. |
| `model` | 요청한 모델 ID의 정확한 일치 필터다. |
| `provider` | 제공자 ID의 정확한 일치 필터다. |

결과는 `experiments`, `page`, `pageSize`, `total`, `totalPages`, `activeCount`를 반환한다. 빈 목록도 `page=1`, `totalPages=1`이며 `total=0`이다. 정렬은 `created_at DESC, id DESC`로 고정한다. 각 목록 행에는 기존 식별자·이름·종류·상태·등록 시각·전체/처리 실행 수와 요청 모델 배열 `models`가 포함된다.

모델·제공자·공격 경로를 함께 지정하면 같은 실험 케이스에서 조건을 만족하는 실험을 찾는다. 경로는 실행 당시 입력 스냅샷을 우선하고, 과거 스냅샷에 없는 경우 당시 연결된 시나리오 버전을 사용한다. 현재 시나리오를 수정하거나 보관해도 과거 실행의 분류를 새 버전으로 바꾸지 않는다.

`activeCount`는 목록 필터와 관계없이 공격 실험·정상 응답 확인·성능 평가 중 대기/실행 중인 실험 수다. 과거 이메일 요약의 상태가 대기/실행 중이어도 포함하지 않는다. 다른 페이지에 실행 중인 평가 작업이 있어도 조회 갱신을 계속할 수 있다. 매개변수 없이 호출하는 기존 `GET /api/experiments`도 이메일 요약을 제외하며, 기존 `{experiments: [...]}` 형식과 해당 세 종류의 최근 100개 제한은 유지한다. `GET /api/experiments/{id}`는 기존 이메일 요약 상세의 조회를 계속 허용한다.

### 모델별 집계

`GET /api/results/models?purpose=attack&vector=all`

- `purpose` 기본값은 `attack`이며 위 세 종류 중 하나를 지정한다. `summary`와 서로 다른 종류를 합산하는 `all`은 HTTP 400으로 거절한다.
- `vector` 기본값은 `all`이며 `direct`/`indirect`는 `purpose=attack`에서만 허용한다.
- 응답에는 `purpose`, `vector`, `defense: "off"`, `generatedAt`, `models`가 포함된다.
- `models`는 **제공자 + 요청한 모델 ID**별 행이다. `model`은 요청 모델, `provider`는 제공자, `returnedModels`는 요약 호출에서 실제 응답에 기록된 모델 이름들이다. 별칭 차이를 확인할 수 있으며, 응답이 없는 실패·대기 실행도 원래 요청 모델 그룹에 남는다.
- 각 행은 실험/실행 수, 상태별 수, 공격 판정, 시간·토큰 평균과 측정 건수, 성능 평가 유사도 및 실험 조건을 반환한다. 프롬프트 본문·응답 본문·파일 원문을 집계 응답에 포함하지 않는다.

## 지표 계산 기준

| 지표 | 기준 |
| --- | --- |
| `experiments` / `total` | 조건에 맞는 고유 실험 수 / 실행 수. 반복 실행은 각각 한 건이다. |
| `succeeded` | 실행이 정상 완료된 수. 공격 성공 수와 다르다. |
| `errors` | `failed`와 `timed_out` 실행 수. |
| `queued`, `running`, `cancelled`, `blocked` | 각 실행 상태를 별도로 집계한다. |
| 공격 성공률 `attack.asr` | `성공 / (성공 + 실패) × 100`. 확정 판정이 없으면 `null`이다. |
| `attack.indeterminate` / `unjudged` | 미확정 / 미판정·적용 불가. 성공률 분모에서 제외한다. |
| `latencyMsMean` | 정상 완료 실행의 기록된 서비스 호출 시간 합계를 실행별로 구한 뒤 평균한다. 큐 대기나 전체 처리 시간이 아니다. |
| `tokens.*Mean` | 정상 완료 실행의 입력/출력/전체 서비스 토큰을 각각 실행별로 합산한 뒤 평균한다. 누적 사용량이나 비용이 아니다. |
| `quality.meanRougeL` | 성능 평가의 정상 완료·확정 채점 응답에 대한 ROUGE-L F1 평균이다. |

공격 판정은 `expected_label=attack`이면서 `succeeded` 또는 `blocked`인 실행에서만 읽는다. 같은 지표의 최신 수동 판정이 있으면 자동 판정보다 우선하며, 수동 미확정도 이전 자동 성공을 대체한다. 같은 종류의 판정 순서는 등록 시각과 ID로 결정한다. 실행 오류·대기·취소를 공격 실패로 바꾸지 않는다. 정상 응답 확인·성능 평가에는 공격 성공률을 표시하지 않는다.

시간·토큰은 `llm_calls`의 `summarize` 및 `security` 호출을 사용하며 재시도 기록도 합산한다. 별도 `evaluator` 호출은 제외한다. 실행의 호출 기록이 완료됐고 서비스 호출이 하나 이상이며, 해당 측정값이 모든 호출에 있을 때만 실행별 합계를 계산한다. 일부 호출 값이 빠졌거나 호출 기록이 불완전하면 해당 지표는 누락으로 취급한다.

`latencyReportedCount`, `tokens.inputReportedCount`, `outputReportedCount`, `totalReportedCount`는 각각 평균에 사용된 실행 수다. 지표별 표본 수가 다를 수 있다. 기록된 0은 유효한 측정값이며, 누락된 값은 `null`과 화면의 `—`로 표시한다. 누락값을 0으로 채우거나 분모에 넣지 않는다.

성능 평가에는 `quality.gradedCount`를 함께 표시한다. ROUGE-L은 기준 요약과의 문자 유사도이며 사실 정확도·완전성·보안 성능이 아니다. 일반 이메일 요약에 성능 평가 점수를 임의로 부여하지 않는다. 채점의 세부 한계는 [SUMMARY-QUALITY.md](SUMMARY-QUALITY.md)를 참고한다.

## 비교 해석과 갱신

모델마다 시나리오와 반복 수, 이메일 구성, 입력 길이, 첨부파일, 실행 시기, 추론 설정 및 판정 버전이 다를 수 있다. 그래프는 관찰된 집계이며 동일 조건의 모델 순위를 보장하지 않는다. 기존 성능 평가 화면의 공통 이메일 비교와도 구분한다.

모델 행의 조건 상세에서 응답 모델 이름, 고유 시나리오/버전 수, 추론 설정 수, 요약 지침 버전, 입력 방식, 유효 판정 버전과 실행 시각을 확인한다. API는 `evaluatorVersionCounts`도 제공한다. 특히 과거 이메일 문맥 입력, `scenario-only-v1`, `attachment-v1`을 같은 공격 조건으로 해석하지 않는다.

실행 중인 작업이 있으면 약 5초 간격으로 목록을 확인하고 이어서 모델 지표를 갱신한다. 다른 페이지·필터로 이동한 후 도착한 이전 요청은 최신 표시를 덮어쓰지 않는다. 수동 판정 저장 후에는 결과 탭의 모델 지표도 갱신한다. 기록과 지표는 개별 읽기 요청 시점의 스냅샷이므로 동시에 진행되는 작업이 있으면 시점 차이가 생길 수 있다. 오류를 명시하고 다시 조회할 수 있게 하며 과거 예시 수치를 대신 표시하지 않는다.

## 이메일 요약 제외 검증

- 폐기 가능한 PostgreSQL에서 결과 조회 테스트 6개를 통과했다. 모의 모델 응답만 사용했다.
- 세 종류와 기존 이메일 요약이 섞인 기록에서 5/1개 페이지, 총 6개·2페이지, 종류별 필터와 기존 목록 API를 확인했다. 실행 중인 과거 요약은 `activeCount`에 포함되지 않는다.
- 기존 요약의 ID별 상세 조회와 저장된 행·실행 상세의 보존을 확인하고, 요약 종류의 목록·집계 요청이 거절되는지 검사했다. 이 검증은 로컬 소스 검증이며 운영 배포 완료를 의미하지 않는다.
