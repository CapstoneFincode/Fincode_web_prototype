# 카테고리 UI 프로토타입 — 2026-10-21

개발 브랜치는 `UI`, 기준은 `main` 병합 커밋 `89c99bf50b04e9f45ce9e27f7f616a89ce3d5300`이다. UI 작업은 김태현(Alphabridge09) 계정으로 저장한다.

## 변경 범위

- 공격 실험은 개별 공격 체크 대신 카테고리를 선택한다. 선택한 카테고리의 활성화된 실행 가능 시나리오 전체를 요청에 넣는다.
- 실제 실행 전 카테고리 수, 시나리오 수, 반복 횟수와 총 호출 횟수를 표시한다. 비활성 시나리오 및 아직 실행할 수 없는 첨부 경로는 제외 수를 표시한다.
- 기존 서버 한도인 시나리오 10개, 반복 10회, 총 100회는 유지한다. 초과 선택을 조용히 잘라내지 않고 요청 전에 차단한다. 대규모 일괄 실행은 별도 후속 범위다.
- 데이터 관리에서 카테고리별 필터 및 정렬, 카테고리 생성, 공격 추가·수정 시 카테고리 선택을 지원한다.
- 카테고리는 공격의 주제이며 직접/간접 구분과 입력/이메일/첨부 삽입 위치는 독립적으로 유지한다.

## DB와 API

신규 `003_attack_categories.sql`을 추가하며 적용된 `001`/`002`는 변경하지 않는다.

- `attack_categories`: 카테고리 ID, 이름, 정규화된 고유 이름, 표시 순서, 생성 정보를 저장한다.
- `attack_scenarios.category_id`: 카테고리 외래키. 기존 사용자 데이터는 미분류로 보존하고, 알려진 합성 예시만 초기 분류한다.
- `GET /api/data`: `categories: [{id, name}]` 및 `attacks[].categoryId`를 추가한다.
- `POST /api/categories`: `{name}`을 받아 카테고리를 만들고 전체 데이터 목록을 반환한다.
- 카테고리가 없는 구형 신규 요청은 미분류로 저장하며, 구형 수정 요청은 기존 분류를 유지한다.
- 시나리오의 카테고리 변경도 새 revision을 만든다. 이미 등록된 실험의 입력과 과거 판정은 수정하지 않는다.
- 새 실험 스냅샷은 당시의 `attackCategoryId`를 보관한다.

초기 카테고리는 시스템 프롬프트 유출, 지시 덮어쓰기, 역할·권한 사칭, 특수 토큰 인젝션, 비가시 문자 은닉, 첨부 콘텐츠 주입, 미분류다. 예시 틀이며 팀이 카테고리와 시나리오를 추가해 확장한다. 빈 카테고리는 공격 데이터가 있다는 뜻이 아니다.

## 검토용 사이트

https://fincode-ui-categories.tinyhawk128.chatgpt.site

기존 운영 사이트와 별도의 비공개 정적 프로토타입이다. `scripts/package-ui-preview.py --output <검토용 사이트>/dist`로 같은 `public/` 화면을 복사하고 `fincode-preview` 메타 표시를 추가한다. 이 표시가 있을 때 모델 연결/호출을 비활성화하고 검토용 브라우저 저장을 사용한다. API 키나 운영 DB 연결은 포함하지 않는다. 실제 모델 실행 결과를 모의로 생성하지 않는다.

실제 운영 반영 시에는 검토된 커밋으로 Python 백엔드를 배포하고 migration 003 적용·카테고리 API를 확인한 뒤 해당 UI를 기존 웹에 배포한다. 카테고리를 지원하지 않는 구형 백엔드에 새 필드를 저장 성공으로 표시하지 않는다. 이번 작업은 UI 브랜치와 검토용 사이트에만 반영하며 main·Railway 운영 DB·기존 웹은 변경하지 않는다.

- 구문 검사와 diff 공백 검사를 통과했다. 브라우저 제어 도구가 없어 실제 브라우저 클릭·시각 검증은 수행하지 못했다.
- 운영 Railway migration 및 실제 카테고리 API 배포는 후속 단계다.
