## 변경 범위

- 공격 실험은 카테고리를 선택한 뒤 각 카테고리에서 실행할 **서로 다른 시나리오 개수**를 지정한다. 새 선택의 기본값은 1개다.
- 각 카테고리의 활성·지원 시나리오 중 **처음 등록한 순서대로 N개**를 고르고 각각 1회 실행한다. 무작위 추출과 공격별 반복 횟수 입력은 사용하지 않는다. 총 호출 수는 카테고리별 선택 개수의 합이다.
- 비활성 시나리오와 아직 지원되지 않는 첨부 경로는 대상에서 제외하고 제외 건수를 표시한다. 빈 값, 0, 소수, 실행 가능한 수를 넘는 값은 요청 전에 차단하며 자동으로 개수를 줄이지 않는다.
- 한 번에 최대 100개 시나리오를 선택할 수 있다. API의 이전 반복 요청 형식은 호환되지만 시나리오 수 × 반복 수가 100회를 넘으면 거절한다. 공격 실험 UI는 항상 `repeat: 1`과 선택한 시나리오 ID만 전송한다.
- **정상 이메일 실험(DB 연결 모드)**은 별도의 반복 횟수를 1~10회로 지정한다(기본 1회). 같은 정상 이메일을 지정한 횟수만큼 실행하며 예정 호출 수도 반복 횟수와 같다. 공격 카테고리별 개수와 독립적으로 유지한다. 빈 값·0·소수·10회 초과는 요청 전에 차단한다.
- 실험 종류를 전환해도 정상 반복 횟수와 공격 선택 개수를 각각 유지한다. 숨겨진 설정은 입력 검증과 실제 요청에 영향을 주지 않는다.
- 저장된 새 계획은 선택한 개수와 시나리오를 고정해 보관한다. 기존 반복 실험·계획은 당시 반복 수를 유지해 표시한다.
- 데이터 관리에서 카테고리별 필터 및 정렬, 카테고리 생성, 공격 추가·수정 시 카테고리 선택을 지원한다.
- 카테고리는 공격의 주제이며 직접/간접 구분과 입력/이메일/첨부 삽입 위치는 독립적으로 유지한다.

## DB와 API

신규 `003_attack_categories.sql`을 추가하며 적용된 `001`/`002`는 변경하지 않는다.

- `attack_categories`: 카테고리 ID, 이름, 정규화된 고유 이름, 표시 순서, 생성 정보를 저장한다.
- `attack_scenarios.category_id`: 카테고리 외래키. 기존 사용자 데이터는 미분류로 보존하고, 알려진 합성 예시만 초기 분류한다.
- `GET /api/data`: `categories: [{id, name}]`, `attacks[].categoryId`, `attacks[].registeredAt`를 제공한다. `registeredAt`은 동일한 논리 ID의 모든 revision 중 가장 이른 생성 시각이며, 수정해도 바뀌지 않는다. 목록도 이 시각 기준으로 정렬한다.
- 브라우저 저장 모드는 신규·복제 시 등록 시각을 만들고 수정 시 유지한다. 등록 시각이 없는 기존 자료는 기존 배열 순서를 유지하며 시각이 있는 자료보다 먼저 배치한다. 같은 시각의 자료도 일정한 순서를 유지한다.
- `POST /api/categories`: `{name}`을 받아 카테고리를 만들고 전체 데이터 목록을 반환한다.
- 카테고리가 없는 구형 신규 요청은 미분류로 저장하며, 구형 수정 요청은 기존 분류를 유지한다.
- 시나리오의 카테고리 변경도 새 revision을 만든다. 이미 등록된 실험의 입력과 과거 판정은 수정하지 않는다.
- 새 실험 스냅샷은 당시의 `attackCategoryId`를 보관한다. 큐는 실험 생성 순서와 해당 실험의 case 번호·반복 번호에 따라 선점한다.

초기 카테고리는 시스템 프롬프트 유출, 지시 덮어쓰기, 역할·권한 사칭, 특수 토큰 인젝션, 비가시 문자 은닉, 첨부 콘텐츠 주입, 미분류다. 예시 틀이며 팀이 카테고리와 시나리오를 추가해 확장한다. 빈 카테고리는 공격 데이터가 있다는 뜻이 아니다.
