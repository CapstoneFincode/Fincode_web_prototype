# 성능 평가 준비

2026-11-09 팀 결정에 따라 기존 이메일 요약기를 유지하고 모델 비교 화면을 분리했다. 왼쪽 **성능 평가** 버튼을 누르면 **이메일 요약기**, **단일 모델 성능 평가**, **모델 별 비교**의 세 하위 메뉴가 펼쳐진다. 접고 펼치기는 현재 화면의 입력과 결과를 다시 렌더링하지 않는다.

## 이메일 요약기 (`#email`)

기존 링크와 모델 선택, 정상 이메일 불러오기, 제목/본문 입력, 실제 한 건 요약, 기준 요약 별도 보기, 토큰/시간 확인과 결과 저장/내보내기를 유지한다. 방어 선택 UI는 제거했다. 실제 요청은 기존 `defense=off`를 유지하고, 기준 정답은 모델 입력에 포함하지 않는다. 결과에 표시되는 방어 미적용은 실제 실행 조건 기록이다.

## 단일 모델 성능 평가 (`#single-evaluation`)

- 현재 제공 모델 목록에서 모델 1개와 방어 조건 초안을 선택한다. 방어 OFF를 기준으로 입력 탐지·명령/데이터 분리·조합에 따른 변화도 준비할 수 있다.
- `state.singleEvaluationDraft`는 비교 설정과 요약기/공격 실험 설정에서 독립적이다. 화면 이동 시 유지되고 새로고침 시 초기화된다.
- 정상 이메일 데이터 현황과 향후 평가 항목을 보여 준다. 평가 실행 버튼은 비활성화하며 자동 채점·모델 호출·DB 저장·실제 방어 적용은 수행하지 않는다.

## 모델 별 비교 (`#comparison`)

- 현재 BAZE에서 조회한 목록에서 기본 2개의 모델을 선택한다. **+ 모델 추가**로 최대 5개까지 늘릴 수 있고, 추가한 항목만 제거할 수 있다. 5개일 때 추가 버튼을 비활성화한다. 중간 항목 제거 시 나머지 모델 선택과 방어 조건은 유지된다. 과거 실험의 모델 표기를 제공 모델처럼 사용하지 않는다. 같은 모델을 선택하면 향후 방어 전후 비교 조건으로 활용할 수 있다.
- 방어 OFF를 기준 조건으로 두고, 추가 비교 조건으로 입력 탐지·명령/데이터 분리·두 기법 조합을 선택할 수 있다. 이들은 아직 구현 전인 후보이며 설정 초안만 변경한다.
- 비교 설정은 `state.comparisonDraft`의 `models` 배열(2–5개)과 `defense`에 독립적으로 보관한다. 요약기의 실제 모델과 공격 계획의 방어 선택에 영향을 주지 않고 네트워크 실행/DB 저장을 하지 않는다. 화면을 오가면 유지되지만 새로고침하면 초기화된다.
- 정상 데이터 수, 정상 라벨 검토 상태와 합성 예시 수를 현재 로드한 데이터 기준으로 보여 준다. 전체 등록 수를 고정 100건으로 표시하지 않는다. 정상 라벨 검토 완료는 기준 요약의 검수 완료와 다르다.
- 요약 품질, 정상 이메일 오차단, 응답시간, 토큰 사용량을 향후 비교 항목으로 안내한다. 측정 결과를 만들지 않으며 비교 실행 버튼은 비활성화한다.

자동 채점, 일괄 실행, 실제 모델 간 비교와 방어 실행은 다음 작업이다. 임의로 새로 입력한 이메일에는 해당 원문에 맞는 기준 요약/핵심 정보가 필요하다.

2026-11-09 운영 등록을 완료했다. 기존 5건을 포함해 정상 이메일은 105건이며, 추가한 100건 전체를 원본과 대조했다. [원본 ID–DB ID 매핑과 보존 검증 결과](verification/2026-11-09-model-evaluation-import.json)를 보관한다.

## 데이터와 검토 상태

- 원본: `datasets/ground_truth_set/v1/emails.json`, `GT-SYN-001`–`GT-SYN-100`.
- 원본 SHA-256: `f8818c7418dc99fe54feb84e63fd5d51430bfeb93362f1e841461cac03a2889d`.
- 기존 정상 예시는 보존하고 합성 100건을 추가한다. 운영 자동 seed에는 넣지 않는다.
- 기존 정상 이메일 API에 제목, 본문, 기준 요약 초안, 필수 핵심 정보와 `reviewStatus=pending`을 전달한다. 서버는 정상 라벨, 합성 출처와 기준 요약 `draft` 상태를 저장한다.
- 인간 검수 완료는 0건이다. 등록 성공이나 구조 검사 통과는 정답 승인과 다르다.
- 원본 ID와 서버가 생성한 ID/UUID/버전은 등록 보고서로 연결한다. 유형, 난이도, 원문 근거, 검토 메모 등 확장 메타데이터는 원본 파일에 보존한다.
- 현재 GET API는 합성 출처를 화면용 `user`로 표시하며 기준 요약의 검토 상태는 반환하지 않는다. `draft` 저장은 기존 백엔드 저장 규칙에 근거한다.

## 운영 등록 절차

`scripts/import-ground-truth.py`는 기본적으로 읽기 전용 사전 검사를 한다. `--apply`를 명시할 때만 기존 `/api/data/normal`에 없는 항목을 순차 등록한다. 접근 토큰은 숨김 입력으로 받고 파일/출력/보고서에 저장하지 않는다.

```bash
python scripts/import-ground-truth.py datasets/ground_truth_set/v1/emails.json \
  --site https://fincode-security-lab.xogus090721.chatgpt.site \
  --report /tmp/fincode-ground-truth-dry-run.json
```

검사 결과를 확인한 뒤 같은 명령에 `--apply`를 추가하고 별도의 등록 보고서 경로를 지정한다.

등록 전 전체 데이터 해시와 충돌을 검사한다. 같은 제목·본문의 항목이 이미 있으면 기준 요약·핵심 정보·검토 상태까지 일치할 때만 재사용한다. 응답이 불확실한 POST는 자동 재시도하지 않고 중단한다. 재실행 전 읽기 전용 검사로 저장 여부를 확인한다. 이 방식은 HTTP 항목별 등록이며 전체 100건을 묶은 DB 트랜잭션은 아니다. 한 번에 한 담당자만 등록 작업을 실행한다.

등록 후 원본 100건을 대조하고 기존 정상 이메일, 공격 시나리오, 카테고리의 내용 보존과 기존 실험 ID의 존재를 확인한다. API 실험 목록은 최신 100건까지이므로 목록 수를 전체 DB 실험 수로 해석하지 않는다. 모델 실행·자동 채점·과거 결과 변경은 수행하지 않는다.

## 다음 단계

기준 요약과 핵심 정보의 사람 검수를 먼저 진행한다. 이후 같은 이메일 버전, 요약 지시, 방어 설정과 반복 조건을 고정하고 기준 정답 자동 채점 및 모델별 비교를 구현한다. 요약 품질과 정상 이메일 거부/오차단, 응답시간·토큰 사용량은 서로 구분해서 비교한다.

팀 로드맵은 공격 실험 버그 수정 → 파일 업로드 → 공격 시나리오 데이터 확충 → 보안 기능 구현이다. 정상 이메일을 활용한 모델 평가 준비는 이 로드맵과 병행한다.
