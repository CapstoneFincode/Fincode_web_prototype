# 합성 정상 이메일의 평가용 승인

2026-11-09 사용자가 합성 정상 이메일 100건을 검토 완료로 처리한 다음 성능 평가 구현을 진행하도록 요청했다. 정상 라벨과 기준 요약은 별도 상태이므로 둘 다 승인 대상으로 삼는다. 승인은 사용자 요청에 따른 데이터셋 사용 승인으로 기록하며, 사람이 100건을 개별 검사했다고 기록하지 않는다.

## 현재 운영 처리 결과

정상 이메일 **라벨 100건은 검토 완료**로 변경하고 재조회로 확인했다. 운영 API 배포가 자동 승인 검토에서 거절되어, 이미 배포되어 있던 버전 보관형 `PUT /api/data/normal/{id}`를 사용했다. 이메일 버전은 각각 1에서 2로 증가했고 이전 버전은 보존된다. 제목·본문·기준 요약·핵심 정보와 다른 정상 예시·공격 데이터·카테고리는 그대로다. [승인 기록](verification/2026-11-09-normal-label-approval.json)에 원본 ID와 변경 전후 DB 버전을 남겼다.

이후 사용자가 운영 배포를 승인해 새 API를 배포했고, 원자적 승인 API로 **기준 요약 100건도 검토 완료**로 처리했다. 승인 도구를 `--apply`로 실행하고 재조회하여 정상 라벨 100건과 기준 요약 100건이 모두 `reviewed`임을 확인했다. 이메일 버전 2, 이메일·정답 ID와 정답 버전, 제목·본문·기준 요약·핵심 정보 및 다른 데이터는 보존됐다. [최종 승인 기록](verification/2026-11-09-ground-truth-approval.json)에 대응 관계와 확인 결과를 남겼다. 원본 JSON의 최초 `pending/draft` 상태는 당시 기록으로 유지한다. 일반적으로 draft 정답을 사용하는 다른 평가는 계속 초안 기준 예비 평가로 구분한다.

## 보존과 승인 절차

- 원본 `datasets/ground_truth_set/v1/emails.json`과 원본 ID–DB ID 등록 매핑을 사용한다. 기존 합성 예시 5건 및 다른 등록 데이터는 대상에서 제외한다.
- `scripts/review-ground-truth.py`는 기본 읽기 전용이다. 원본과 현재 DB의 제목·본문·기준 요약·핵심 정보가 모두 같은 100건인지 확인한다.
- `--apply`를 지정하면 `POST /api/data/normal/review`를 호출한다. 서버가 이메일 및 정답의 최신 버전과 내용 해시를 모두 확인한 후 한 트랜잭션에서 검토 상태, 승인자·시각·메모만 변경한다. 충돌하면 전체 승인을 취소한다.
- 이미 승인된 항목의 메모·시각은 재요청으로 덮어쓰지 않는다. 본문·정답·핵심 정보·버전·출처·공격 데이터·실험 기록은 변경하지 않는다.
- 승인 후 다시 읽어 100건의 정상 라벨과 기준 요약이 `reviewed`인지, 내용과 다른 데이터가 보존됐는지 확인하고 보고서를 남긴다. 접근 토큰은 숨김 입력으로만 받으며 보고서나 파일에 저장하지 않는다.

## AI 보조 점검 범위

원본 구조 검사 오류·경고는 없고 100건의 핵심 정보 468개에는 대응하는 원문 근거가 있다. AI 보조 내용 점검에서 명백한 날짜·금액 모순이나 모델 지시를 겨냥한 공격문은 발견하지 못했다. 이는 개인별 사람 검수나 데이터 대표성을 입증하는 결과는 아니다.

기준 요약은 간결한 예시이며 모든 핵심 정보를 반드시 포함하지는 않는다. GT-SYN-070(비밀번호·인증번호 메일 요청 없음), 076(새 안내서 수정 제외), 077(습기 잔류 시 밀봉 금지), 096(참가자 이동 예약 제외)은 해당 조건을 기준 요약에서 생략한다. 073(평균 미확정), 037(외부 배포 금지)은 간접적으로 표현한다. 이 정보들은 원문과 `requiredFacts`에 보존되어 있다.

따라서 기준 요약과의 유사도와 핵심 정보 확인을 별도로 측정한다. 유사도 점수를 사실 정확도나 정답률로 해석하지 않으며, 자동 확인하기 어려운 표현은 검토 필요로 남긴다. 원본 데이터의 `humanReviewCompleted: false` 기록은 구조 검사 당시의 사실로 보존한다.
